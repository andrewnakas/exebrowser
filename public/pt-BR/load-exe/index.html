Abra um arquivo EXE e execute aqui

Roda com Wine 1.7.55 (Win32) + Boxedwine sobre WebAssembly · Nada é enviado · Sem conta

Solte abaixo um executável do Windows — ou a pasta inteira, ou um zip dela — e ele roda dentro desta aba. O arquivo é lido no seu próprio aparelho e copiado para uma unidade C:\ virtual que existe apenas na memória da aba. Não há servidor nenhum executando, não há instalador e não fica nada para trás quando você fecha a página.

O primeiro início baixa o motor do Wine (~30–60 MB) e guarda em cache. Clique na tela para entregar o mouse e o teclado a ela; aperte Esc para recuperá-los.

Qual das três opções usar

As três terminam no mesmo lugar — os arquivos montados na unidade virtual — mas servem para coisas diferentes, conforme o que você tem no disco.

  • Um único EXE: para um programa autossuficiente — um utilitário antigo, um jogo de arquivo único, uma ferramenta portátil. Se num PC de verdade ele roda com um duplo clique e mais nada, é esta a opção.
  • Uma pasta: para qualquer coisa com .dll, .dat, .ini ou arquivos de dados ao lado. Isso é a maior parte do software real, e é justamente a opção que as pessoas pulam antes de concluir que o programa não funciona. A pasta é montada inteira e você escolhe qual .exe inicia.
  • Um zip: o mesmo que uma pasta, para quando você tem o arquivo compactado em vez do diretório já extraído. Útil em navegadores de celular, que não oferecem seleção de pasta.

Se o programa precisa de um arquivo para trabalhar — um compactado para abrir, um documento para carregar — coloque-o na pasta também antes de enviá-la. Nada dentro da aba enxerga o seu disco de verdade, então tudo o que o programa precisar abrir tem de entrar junto com ele.

O que roda e o que honestamente não roda

Isto é um ambiente Windows de 32 bits emulado, e não uma camada de compatibilidade sobre a sua máquina real. Vale saber onde fica a fronteira antes de gastar um download com isso.

Funciona bem

  • Aplicativos Win32 e GDI de 32 bits de mais ou menos 1995 a 2008: editores, visualizadores, calculadoras, compactadores, pequenos utilitários.
  • Jogos 2D daquela época, inclusive vários que já nem iniciam no Windows 11.
  • Instaladores antigos, quando o que você quer são os arquivos de dentro e não um sistema instalado.
  • Software de 16 bits para Windows 3.x, usando o motor Wine 3.1 · 16 bits no seletor acima.

Geralmente não funciona

  • Programas de 64 bits. O motor padrão é só de 32 bits. Existe um ambiente experimental de 64 bits com carregador próprio, mas muita coisa ainda não desenha direito nele.
  • Direct3D e jogos 3D modernos. Aqui não há acesso à GPU.
  • .NET, os runtimes modernos do Visual C++ e tudo que espere APIs do Windows 10. O Wine 1.7.55 é anterior a eles.
  • Qualquer coisa que precise de rede, servidor de licença ou hardware real: chaves USB, impressoras, portas seriais, verificação de disco.

A velocidade fica entre 10% e 40% da nativa, porque cada instrução x86 é emulada. Suficiente para um utilitário ou um jogo antigo; insuficiente para qualquer coisa pesada. O guia de compatibilidade detalha as categorias, e nós testamos 53 aplicativos reais e publicamos o que aconteceu com cada um.

Se não iniciar

  1. Carregue a pasta, não o EXE sozinho. Uma DLL faltando ao lado do programa é de longe a falha mais comum, e normalmente se manifesta como absolutamente nada acontecendo.
  2. Confira se é de 32 bits. Muitos downloads hoje entregam a versão de 64 bits por padrão; a de 32 bits da mesma versão costuma rodar bem aqui.
  3. Tente outro motor. O Boxedwine 18R2 às vezes roda o que o padrão engasga, e um programa que pede o Internet Explorer precisa da opção + Gecko.
  4. Leia o console. A seção Saída do console abaixo da tela mostra do que o Wine reclamou de verdade: quase sempre uma DLL específica faltando ou uma chamada não implementada.
  5. Pode ser um instalador, e não o programa. Execute assim mesmo, deixe descompactar e depois use Baixar os arquivos que este programa gravou para tirar o que ele gerou. Extrair um instalador antigo cobre as alternativas.

Para onde vai o seu arquivo

Para lugar nenhum. O .exe é lido localmente com a API de arquivos do navegador e gravado num sistema de arquivos em memória que o Wine enxerga como C:\. Nenhuma parte dele é transmitida, e não existe cópia no servidor para apagar porque ela nunca chega a ser feita. Ao fechar a aba, a unidade virtual desaparece; os arquivos que um programa salvar ficam guardados só neste navegador, para você retomar de onde parou, e Baixar os arquivos que este programa gravou entrega uma cópia que é sua.

Nenhum dos dois consegue ver o seu arquivo, a unidade virtual ou qualquer coisa que o programa faça: são scripts comuns no nível da página, e a memória do emulador não é algo a que eles tenham acesso. Perguntas frequentes

Meu EXE é enviado para algum servidor?

Não. O arquivo é lido por JavaScript no seu próprio aparelho e copiado para uma unidade C:\ em memória dentro da aba. Ele não é enviado a lugar nenhum e some quando você fecha a aba.

Que programas de Windows realmente rodam?

Software de Windows de 32 bits de mais ou menos 1995 a 2008 é o que funciona melhor: pequenos utilitários, aplicativos Win32 e GDI, instaladores antigos e jogos 2D. Programas de 64 bits, qualquer coisa que precise de Direct3D, .NET ou um runtime moderno, e tudo que espere hardware real ou acesso à internet são as falhas de sempre.

Meu programa precisa de DLLs ao lado dele. O que eu faço?

Carregue a pasta inteira ou um zip dela, em vez do .exe sozinho. Escolher uma pasta ou um zip monta todos os arquivos na unidade C:\ virtual, e aí você escolhe qual é o executável de entrada.

Consigo recuperar os arquivos que o programa gravar?

Sim. Baixar os arquivos que este programa gravou empacota num zip tudo o que o programa escreveu na unidade C:\ virtual: saves, documentos exportados, o conteúdo que um instalador descompactou.

Funciona num Chromebook ou num notebook de trabalho bloqueado?

Sim, porque nada é instalado. É uma página web usando WebAssembly, então roda onde rodar um Chrome, Edge, Firefox ou Safari atual — inclusive em máquinas gerenciadas em que você não pode instalar software.

Por que está lento?

Cada instrução x86 é emulada no seu navegador, então conte com algo entre 10% e 40% da velocidade nativa. Tudo bem para utilitários, jogos 2D antigos e instaladores; ruim para qualquer coisa exigente.
