O que é um arquivo .exe — e como abrir um?

Por Andrew Nakas · Publicado em 22 de setembro de 2026 · ~8 minutos de leitura

Quase todo mundo encontra essa pergunta do mesmo jeito: alguma coisa baixou um arquivo terminado em .exe, e dar dois cliques não serviu para nada. Talvez você esteja num Mac. Talvez esteja num notebook do trabalho que não deixa instalar nada. Talvez seja mesmo um PC com Windows e ele ainda assim se recusou a iniciar.

Aqui você vê o que o arquivo realmente é, como abrir um em cada plataforma, como olhar dentro sem executar e — a parte que quase todo guia pula — quando você não deveria abrir de jeito nenhum.

O que um .exe realmente é

Um .exe é um programa, não um documento. Abrir não exibe nada; ele manda o seu sistema operacional começar a executar o código de máquina que está lá dentro. É essa a razão inteira de o resto deste artigo ser mais complicado do que “dê dois cliques”.

Tecnicamente é um arquivo PE — Portable Executable, o formato da Microsoft desde o Windows NT. Dentro, um PE contém:

  • Um pequeno stub de DOS logo no começo, herança dos anos 1980. É por causa dele que um .exe antigo rodado no DOS imprime “This program cannot be run in DOS mode”.
  • Um cabeçalho PE descrevendo para qual CPU o código foi feito (x86 de 32 bits, x64 de 64 bits, ARM), qual versão do Windows ele espera e onde cada coisa fica na memória.
  • Seções com o código de máquina propriamente dito, os dados fixos e os recursos — ícones, layouts de diálogo, texto embutido.
  • Uma tabela de importações listando as bibliotecas do Windows de que ele precisa, como kernel32.dll ou user32.dll.

Essa tabela de importações é a razão de um .exe raramente se bastar. Ele pressupõe que o Windows existe ao redor. Entregue o mesmo arquivo ao macOS ou ao Linux e ninguém ali fala a língua dele — o arquivo está ótimo, o público é que está errado.

Outras duas coisas usam a mesma extensão e se comportam de outro jeito: instaladores (um programinha cuja função é desempacotar um programa de verdade no seu disco) e arquivos autoextraíveis (um zip com um descompactador parafusado na frente). As duas importam mais adiante.

Abrindo um no Windows

Dê dois cliques. Esse é realmente o procedimento inteiro, e se tivesse funcionado você não estaria lendo isto. Quando não funciona, quase sempre é uma destas coisas:

  • O SmartScreen bloqueou. Aparece uma caixa azul de “O Windows protegeu o seu computador”. Se você tem certeza da origem, “Mais informações” → “Executar assim mesmo”. Se não tem certeza, pare — veja a seção de segurança mais abaixo.
  • Ele precisa de direitos de administrador. Botão direito → “Executar como administrador”. Instaladores geralmente precisam.
  • Ele é de 16 bits. Nada da era Windows 3.x inicia num Windows de 64 bits; o subsistema foi removido. Veja rodar software de 16 bits do Windows 3.x.
  • Falta uma DLL. Um erro que nomeia uma .dll específica significa que o programa espera uma biblioteca ou um runtime que você não tem. Normalmente o arquivo precisa ficar na pasta original, ao lado dos companheiros dele.
  • Ele é simplesmente velho. Por que programas antigos não rodam no Windows 11 cobre as opções de modo de compatibilidade.

Abrindo um no Mac

O macOS não consegue rodar um .exe nativamente e nunca conseguiu — convenções de CPU diferentes no Apple Silicon e, de todo modo, um sistema operacional completamente diferente embaixo. Renomear o arquivo não faz nada. Suas opções realistas, ordenadas com honestidade:

  • Rodar numa aba do navegador. Nada para instalar, e funciona igual em Intel e em Apple Silicon. É o que o carregador deste site faz — uma compilação em WebAssembly do Wine mais um emulador de x86, rodando localmente na aba. Seu arquivo nunca é enviado para lugar nenhum. O limite é real e merece ser dito: ele mira o software Win32 clássico de 32 bits, mais ou menos de 1995 a 2008, a cerca de 10–40% da velocidade nativa. Um utilitário antigo ou um jogo velho, sim. Aplicativos modernos de 64 bits, não.
  • Instalar o Wine ou o CrossOver. Mais capaz e bem mais trabalhoso de configurar. O Wine é gratuito; o CrossOver é comercial e dá mais apoio.
  • Uma máquina virtual. Parallels ou VMware com uma licença de Windows de verdade. É a resposta mais compatível e também a mais cara, em dinheiro e em espaço em disco.
  • Boot Camp. Só em Macs com Intel. Acabou no Apple Silicon.

Se o objetivo é “abrir este programa antigo uma vez”, o caminho do navegador costuma ser o proporcional. Se o objetivo é “rodar software Windows com frequência neste Mac”, o que você quer mesmo é uma VM.

Num Chromebook

A mesma situação do macOS, com um detalhe a mais: Chromebooks gerenciados de escolas e empresas muitas vezes proíbem instalar qualquer coisa, inclusive o contêiner Linux. O caminho do navegador, que não instala nada, é com frequência o único que não está bloqueado, e funciona também em Chromebooks ARM, porque a CPU é emulada de qualquer jeito. Escrevemos sobre isso separadamente — quatro maneiras de rodar software Windows num Chromebook.

No Linux

Instale o Wine pelo gerenciador de pacotes da sua distribuição e depois wine programa.exe. O Linux tem a melhor história nativa fora do próprio Windows: o Wine é maduro e, para jogos, o Proton da Valve é construído em cima dele. Se você preferir não instalar nada, o caminho do navegador funciona aqui também.

No Android e no iOS

Sendo honesto: na maior parte das vezes não dá, e guias que sugerem o contrário estão desperdiçando o seu tempo. Não existe uma forma suportada de rodar software Windows no iOS. No Android existem emuladores que dão boot num ambiente Windows inteiro, mas eles são lentos e chatos de configurar. Uma aba do navegador abre programas clássicos pequenos nos dois, o que é uma régua genuinamente baixa — serve para dar uma olhada num jogo antigo, não para trabalho de verdade.

Se você só quer ver o que tem dentro

Muitas vezes o objetivo real não é rodar o programa. Você quer um arquivo de dentro dele — um documento, uma imagem, um driver, um arquivo de dados de algo que não instala mais. Para isso não é preciso executar nada.

  • Tente primeiro uma ferramenta de compactação. Muitos instaladores e todos os autoextraíveis abrem direto no 7-Zip como se fossem zips comuns. Botão direito → “Abrir arquivo”. Também dá para fazer isso no navegador com o extrator daqui.
  • Instaladores têm os próprios desempacotadores. O innoextract lida com o Inno Setup, o cabextract com os baseados em CAB, e msiexec /a faz uma extração administrativa de um .msi. Passo a passo completo: como extrair arquivos de um instalador antigo.
  • Para inspecionar o executável em si — o que ele importa, que recursos carrega, se é de 32 ou 64 bits — o que você quer é um visualizador de PE, não um programa que o abra. Isso responde “o que é esta coisa” sem nunca executá-la.

Esse caminho é também o seguro. Ler um arquivo não é a mesma coisa que executá-lo.

Antes de abrir um: é seguro?

Um .exe pode fazer tudo o que a sua conta de usuário pode fazer. Quase todo guia enterra isso; aqui merece ser o parágrafo mais alto.

  • De onde veio? O site do próprio fabricante é uma coisa bem diferente de um anexo de e-mail, de um agregador de downloads ou de um link num chat. Se você não consegue nomear a origem, não execute.
  • O nome parece armado? nota-fiscal.pdf.exe não é um PDF. O Windows esconde extensões conhecidas por padrão, que é exatamente o que esse truque explora.
  • Passe um antivírus. Envie ao VirusTotal para conferir contra dezenas de motores antes de executar qualquer coisa de que você não tenha certeza.
  • Não confie num crack ou keygen “corrigido”. Essa categoria é o mecanismo de entrega de malware mais confiável da internet.
  • Prefira extrair a executar quando você só precisa de um arquivo de dentro, usando as ferramentas acima.

O isolamento do navegador ajuda em parte disso, não em tudo: um programa rodando numa aba não tem acesso ao seu sistema de arquivos real, então não consegue criptografar os seus documentos. É uma fronteira de contenção de verdade, não uma licença para rodar coisas em que você não tem motivo nenhum para confiar.

Respostas rápidas

  • Dá para converter um .exe em outra coisa? Não. Conversores que anunciam isso ou estão extraindo um arquivo compactado ou não estão vendendo nada. O código lá dentro mira uma CPU e um sistema operacional específicos.
  • Por que aparece “This program cannot be run in DOS mode”? Você está vendo o stub de DOS. Significa que um executável do Windows foi rodado em algum lugar que não é o Windows.
  • Não acontece nada quando dou dois cliques. Muitas vezes é um programa de console que abriu, imprimiu e saiu na hora. Abra um terminal e rode a partir dele para a janela ficar.
  • Dá para abrir um .exe sem Windows? Dá — com Wine no Mac ou no Linux, com uma máquina virtual, ou numa aba do navegador para programas clássicos menores.

A versão curta

Um .exe é um programa do Windows, então “abrir” significa executar, e é por isso que é fácil no Windows e desconfortável em todo o resto. Se você precisa usá-lo, escolha pela plataforma e pela frequência: uma aba do navegador para um programa antigo avulso, o Wine para uso regular, uma VM para qualquer coisa moderna. Se você só precisa tirar algo de dentro, use uma ferramenta de compactação e não execute nada. E, seja qual for o caminho, descubra antes de onde o arquivo veio.

Se você prefere olhar antes de pular, o visualizador de EXE lê tudo isso de um arquivo para você — cabeçalhos, bibliotecas, ícone, assinatura — no navegador, sem executar nada.
