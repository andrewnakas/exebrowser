.exe 文件到底是什么

.exe 是为 Windows 编译出来的程序。它不是文档，不是压缩包，也不是视频——它是一串机器指令，加上一个告诉 Windows 该怎么装载它们的文件头。这也是「打开方式」对它从来没用的原因：程序没有对应的查看器，因为程序本身就是那个应用。

这同时解释了大家来到这里的两种处境。要么你在 Mac、Linux 或 Chromebook 上，Windows 程序根本跑不起来；要么你就在 Windows 上，而文件因为少数几个具体原因之一启动不了。这是两个不同的问题，答案也不同。

最快能试的一招

这个网站在浏览器标签页里运行 Windows 程序。把一个 .exe 拖到加载页面上，它就会尝试在本地运行：文件在你自己的机器上被读取，不会上传到任何地方。

限制也得说清楚，因为它们是真实存在的：这里最适合大约 1995 到 2008 年之间的 32 位 Windows 软件。小工具和老游戏是最佳区间。任何需要现代 .NET、真实网络访问或 3D 图形环境的东西都跑不了，而我们把失败的例子和成功的一起写出来，而不是假装它们不存在。

在各个平台上怎么打开 .exe

在 Mac 上

macOS 无法原生运行 .exe 文件：操作系统不同，而自 Apple Silicon 之后处理器架构也不同。双击只会得到一个错误，换多少种「打开方式」都改变不了。

真正可行的办法有三种：像 Wine 或 CrossOver 这样的兼容层，它翻译 Windows API 调用，而不是模拟一整台 PC；跑着正版 Windows 的虚拟机；或者，对于又老又小的程序，直接在这里的浏览器标签页里运行。浏览器这条路什么都不用装，这往往就是决定性的因素。

在 Chromebook 上

ChromeOS 完全无法安装 Windows 软件，这是设计使然，不是疏漏。没有 Wine 可装，没有 Program Files，安装程序也无处可去。

剩下的就是在浏览器里运行——也就是这个网站做的事——或者用 Linux 容器，前提是你的 Chromebook 开启了它，而且你愿意在里面装 Wine。我们还有一篇更长的文章讲这四种办法，按麻烦程度排了序。

在 Linux 上

用发行版的包管理器装上 Wine，然后 wine 你的程序.exe。Wine 已经相当成熟，很多软件第一次就能跑起来。跑不起来的时候它通常会大声报错，直接说出缺了哪个 DLL 或哪个 API，至少给了你一个可以去搜的关键词。

在 Windows 上，当它就是不启动

如果连 Windows 自己都拒绝运行一个 Windows 程序，可能的原因就那么几个，而且错误信息通常已经指明了是哪一个：

  • 「此应用无法在你的电脑上运行」。多半是一个 16 位程序。64 位 Windows 移除了运行它们的子系统，没有任何设置能把它找回来。
  • 提示缺少某个 DLL。相对来说算是好消息：程序需要一个你没装的运行库。通常是 Visual C++ 可再发行组件、Visual Basic 6 运行库，或 .NET Framework 3.5。
  • SmartScreen 拦截了它。Windows 不认识这个发布者。如果你确信文件的来源，点「更多信息」再点「仍要运行」。
  • 什么都没发生。常见的情况是一个控制台程序打开、运行、又关掉了，快到你看不见。试着从命令提示符里运行，窗口就会留着。

这几种情况在为什么老程序在 Windows 11 上跑不起来里讲得更细。

当你根本不想运行它的时候

有时候目的并不是运行这个程序，而是拿到它里面的东西。安装包尤其如此，它们通常就是加了一层外壳的压缩包；而非常多的老应用一旦解开就是绿色软件——一个文件夹，从不碰注册表就能运行。

我们的解压工具能打开自解压 .exe，也能打开 7z、ZIP、RAR 等等，全程在浏览器里完成，不上传任何东西。完整的操作说明讲了它处理不了的情况，以及那时该用什么。

如果你只想知道这个文件是什么，EXE 查看器会读取它的文件头，告诉你它是为哪种处理器编译的、加载了哪些系统库、图标长什么样、有没有签名——一行代码都不会执行。

而如果你正在权衡要不要运行它，这个 .exe 安全吗？逐一讲了值得做的每一项检查，以及每一项到底能证明什么。

运行任何东西之前

一个来路不明的 .exe，你的用户账户能做什么，它就能做什么。这不是危言耸听，这就是「程序」的定义。有两件事值得做：把文件拿到 VirusTotal 上查一下；宁可从原厂下载，也别用那些把它重新包进自家安装器的下载站。

在浏览器标签页里运行，确实比在本机直接运行安全得多，因为浏览器沙箱是一道真实的边界，程序拿不到你真正的文件系统。这不等于可以拿来跑恶意软件，但对于一个你拿不准的文件，这是个合理的查看方式。

更安全的做法是根本不运行。读一读文件头不花任何代价，却能回答大部分日常问题：架构对不对、它是安装包还是程序本体、有没有署名的发布者、有没有签名、是不是被加了壳以至于不运行就什么都看不出来。

常见问题

不下载任何东西，能在线打开 .exe 文件吗？

你可以在这里运行一个，什么都不用装——这通常就是这个问题真正的意思。文件由你自己机器上的浏览器读取，不会上传到服务器。体积较小的 32 位 Windows 程序效果最好。

在 Mac 上怎么打开 .exe？

原生打不开。可以用 Wine 或 CrossOver、装 Windows 的虚拟机，或者在浏览器标签页里运行。对又老又小的程序来说，浏览器省事得多。

双击之后什么都没发生，为什么？

通常是一个控制台程序开了又立刻关掉，或者缺少某个运行库而悄悄失败了。从命令提示符里运行它，就能看到错误，不用靠猜。

打开 .exe 文件安全吗？

它只有来源那么安全。一个程序能做你的账户能做的一切。拿到 VirusTotal 上查一查，优先选厂商自己的下载；如果拿不准，在浏览器沙箱里运行比在本机运行安全得多。

如果它是 64 位的呢？

这里的运行时是 32 位的，所以纯 64 位程序装载不了。2010 年之前的很多应用同时也发布了 32 位版本，那个通常能跑。
