Qu'est-ce qu'un fichier .exe ?

Par Andrew Nakas · Publié le 22 septembre 2026 · ~8 minutes de lecture

La plupart des gens rencontrent la question de la même façon : quelque chose a téléchargé un fichier se terminant par .exe, et un double-clic n'a rien donné d'utile. Vous êtes peut-être sur un Mac. Peut-être sur un portable professionnel qui ne vous laisse rien installer. Ou peut-être s'agit-il bel et bien d'un PC Windows, et le fichier a quand même refusé de démarrer.

Cet article explique ce qu'est réellement ce fichier, comment l'ouvrir sur chaque plateforme, comment regarder à l'intérieur sans l'exécuter et — ce que la plupart des guides passent sous silence — quand il vaut mieux ne pas l'ouvrir du tout.

Ce qu'est réellement un .exe

Un .exe est un programme, pas un document. L'ouvrir n'affiche rien : cela demande à votre système d'exploitation de commencer à exécuter le code machine qu'il contient. C'est toute la raison pour laquelle la suite de cet article est plus compliquée qu'un simple « double-cliquez dessus ».

Techniquement, c'est un fichier PE — Portable Executable, le format de Microsoft depuis Windows NT. Un PE contient :

  • Un petit stub DOS tout au début, vestige des années 1980. C'est pour cela qu'un ancien .exe lancé sous DOS affiche « This program cannot be run in DOS mode ».
  • Un en-tête PE qui décrit le processeur visé par le code (x86 32 bits, x64 64 bits, ARM), la version de Windows attendue et l'emplacement de chaque élément en mémoire.
  • Des sections contenant le code machine proprement dit, les données fixes et les ressources : icônes, mises en page des boîtes de dialogue, texte intégré.
  • Une table d'importation qui liste les bibliothèques Windows dont il a besoin, comme kernel32.dll ou user32.dll.

C'est à cause de cette table d'importation qu'un .exe se suffit rarement à lui-même. Il s'attend à ce que Windows existe autour de lui. Confiez le même fichier à macOS ou à Linux, et personne là-bas ne parle sa langue : le fichier n'a rien, c'est le public qui n'est pas le bon.

Deux autres choses portent la même extension et se comportent différemment : les installateurs (un petit programme dont le rôle est de déployer un vrai programme sur votre disque) et les archives auto-extractibles (un zip avec un décompresseur greffé à l'avant). Les deux auront leur importance plus loin.

C'est à l'ouverture que la plupart des gens bloquent ; voici donc la version courte pour chaque plateforme. Le guide pas à pas complet, avec chaque erreur que Windows affiche quand il refuse, se trouve dans comment ouvrir un fichier EXE.

L'ouvrir sous Windows

Double-cliquez dessus. C'est vraiment toute la procédure, et si elle avait fonctionné, vous ne seriez pas en train de lire ceci. Quand ça ne marche pas, c'est presque toujours l'une de ces raisons :

  • SmartScreen l'a bloqué. Une fenêtre bleue « Windows a protégé votre ordinateur » apparaît. Si vous êtes certain de la provenance : « Informations complémentaires » → « Exécuter quand même ». Si vous n'en êtes pas certain, arrêtez-vous et lisez la section sur la sécurité plus bas.
  • Il a besoin des droits d'administrateur. Clic droit → « Exécuter en tant qu'administrateur ». C'est généralement le cas des installateurs.
  • Il est en 16 bits. Rien de l'époque de Windows 3.x ne démarre sous un Windows 64 bits ; le sous-système a été supprimé. Voir exécuter des logiciels Windows 3.x 16 bits.
  • Une DLL manque. Une erreur qui nomme une .dll précise signifie que le programme attend une bibliothèque ou un runtime que vous n'avez pas. En général, le fichier doit se trouver dans son dossier d'origine, avec les fichiers qui l'accompagnent.
  • Il est tout simplement ancien. Pourquoi les anciens programmes ne démarrent pas sous Windows 11 présente les options du mode de compatibilité.

L'ouvrir sur Mac

macOS ne peut pas exécuter nativement un .exe, et ne l'a jamais pu : des conventions de processeur différentes sur Apple Silicon et, dans tous les cas, un système d'exploitation complètement différent en dessous. Renommer le fichier ne sert à rien. Vos options réalistes, classées honnêtement :

  • L'exécuter dans un onglet du navigateur. Rien à installer, et cela fonctionne de la même façon sur Intel et sur Apple Silicon. C'est ce que fait le lanceur de ce site : une version WebAssembly de Wine associée à un émulateur x86, qui tourne localement dans l'onglet. Votre fichier n'est jamais envoyé nulle part. La limite est réelle et mérite d'être dite : il vise les logiciels Win32 32 bits classiques, d'environ 1995 à 2008, à environ 10 à 40 % de la vitesse native. Un utilitaire d'un autre âge ou un vieux jeu, oui. Les applications 64 bits modernes, non.
  • Installer Wine ou CrossOver. Plus puissant, mais bien plus de configuration. Wine est gratuit ; CrossOver est commercial et vous guide davantage.
  • Une machine virtuelle. Parallels ou VMware avec une vraie licence Windows. La solution la plus compatible, et la plus coûteuse, en argent comme en espace disque.
  • Boot Camp. Uniquement sur les Mac Intel. Disparu sur Apple Silicon.

Si l'objectif est d'« ouvrir ce vieux programme une fois », la voie du navigateur est généralement la plus proportionnée. Si l'objectif est d'« exécuter régulièrement des logiciels Windows sur ce Mac », c'est une machine virtuelle qu'il vous faut vraiment.

Sur Chromebook

Même situation que sous macOS, avec une complication supplémentaire : les Chromebooks gérés des écoles et des entreprises interdisent souvent toute installation, y compris celle du conteneur Linux. La voie du navigateur, sans installation, est souvent la seule qui ne soit pas bloquée, et elle fonctionne aussi sur les Chromebooks ARM, puisque le processeur est émulé de toute façon. Nous y avons consacré un article à part : quatre façons d'exécuter des logiciels Windows sur un Chromebook.

Sous Linux

Installez Wine depuis le gestionnaire de paquets de votre distribution, puis lancez wine programme.exe. Linux est, après Windows lui-même, la plateforme la mieux lotie : Wine est mûr et, pour les jeux, Proton de Valve s'appuie dessus. Si vous préférez ne rien installer, la voie du navigateur fonctionne ici aussi.

Sur Android et iOS

Pour être franc : la plupart du temps, ce n'est pas possible, et les guides qui prétendent le contraire vous font perdre votre temps. Il n'existe aucun moyen officiel d'exécuter des logiciels Windows sur iOS. Sur Android, il existe des émulateurs qui démarrent un environnement Windows complet, mais ils sont lents et capricieux. Un onglet du navigateur ouvrira de petits programmes classiques sur l'un comme sur l'autre, ce qui reste une barre vraiment basse : utile pour jeter un œil à un vieux jeu, pas pour travailler sérieusement.

Si vous voulez seulement voir ce qu'il contient

Très souvent, le véritable objectif n'est pas du tout d'exécuter le programme. Vous voulez en sortir un fichier : un document, une image, un pilote, un fichier de données d'un logiciel qui ne s'installe plus. Pour cela, nul besoin d'exécuter quoi que ce soit.

  • Essayez d'abord un outil d'archives. Beaucoup d'installateurs et toutes les archives auto-extractibles s'ouvrent directement dans 7-Zip comme s'il s'agissait de zips ordinaires. Clic droit → « Ouvrir l'archive ». Vous pouvez aussi le faire dans le navigateur avec l'extracteur d'archives d'ici.
  • Les installateurs ont leurs propres outils d'extraction. innoextract gère Inno Setup, cabextract les installateurs basés sur CAB, et msiexec /a effectue une extraction administrative d'un .msi. Guide complet : comment extraire les fichiers d'un ancien installateur.
  • Pour inspecter l'exécutable lui-même — ce qu'il importe, les ressources qu'il contient, s'il est en 32 ou en 64 bits —, il vous faut une visionneuse PE plutôt qu'un outil pour l'ouvrir. Elle répond à la question « qu'est-ce que c'est que ce truc » sans jamais l'exécuter.

C'est aussi la voie sûre. Lire un fichier n'est pas l'exécuter.

Avant d'en ouvrir un : est-ce sûr ?

Un .exe peut faire tout ce que votre compte utilisateur peut faire. La plupart des guides enterrent cette information ; elle mérite d'être ici le paragraphe le plus visible.

  • D'où vient-il ? Le site de l'éditeur lui-même n'a rien à voir avec une pièce jointe, un agrégateur de téléchargements ou un lien reçu dans une messagerie. Si vous ne savez pas nommer la source, ne l'exécutez pas.
  • Le nom paraît-il conçu pour tromper ? facture.pdf.exe n'est pas un PDF. Windows masque par défaut les extensions connues, et c'est exactement sur cela que repose cette astuce.
  • Analysez-le. Envoyez-le sur VirusTotal pour le faire vérifier par des dizaines de moteurs avant d'exécuter quoi que ce soit dont vous n'êtes pas sûr.
  • Ne vous fiez pas à un crack ou un keygen « corrigé ». Cette catégorie est le moyen de diffusion de logiciels malveillants le plus fiable d'internet.
  • Préférez l'extraction à l'exécution quand vous n'avez besoin que d'un fichier à l'intérieur, avec les outils ci-dessus.

Le bac à sable du navigateur aide pour une partie de ces risques, pas pour tous : un programme qui tourne dans un onglet n'a aucun accès à votre véritable système de fichiers, il ne peut donc pas chiffrer vos documents. C'est une vraie barrière de confinement, pas un permis d'exécuter des choses auxquelles vous n'avez aucune raison de faire confiance.

Réponses rapides

  • Puis-je convertir un .exe en autre chose ? Non. Les convertisseurs qui le promettent soit extraient une archive, soit ne vous vendent rien du tout. Le code qu'il contient vise un processeur et un système d'exploitation précis.
  • Pourquoi affiche-t-il « This program cannot be run in DOS mode » ? Vous voyez le stub DOS. Cela signifie qu'un exécutable Windows a été lancé ailleurs que sous Windows.
  • Il ne se passe rien quand je double-clique. Souvent, un programme en console qui s'est ouvert, a affiché quelque chose et s'est refermé aussitôt. Ouvrez un terminal et lancez-le depuis celui-ci pour que la fenêtre reste ouverte.
  • Peut-on ouvrir un .exe sans Windows ? Oui : avec Wine sur Mac ou sous Linux, avec une machine virtuelle, ou dans un onglet du navigateur pour les petits programmes classiques.

En bref

Un .exe est un programme Windows : « l'ouvrir », c'est l'exécuter, et c'est pourquoi c'est facile sous Windows et malcommode partout ailleurs. Si vous avez besoin de l'utiliser, choisissez selon la plateforme et la fréquence : un onglet du navigateur pour un vieux programme ponctuel, Wine pour un usage régulier, une machine virtuelle pour tout ce qui est moderne. Si vous avez seulement besoin d'en extraire quelque chose, utilisez un outil d'archives et ne l'exécutez jamais. Et quelle que soit la voie choisie, sachez d'abord d'où vient le fichier.

Si vous préférez regarder avant de sauter, la visionneuse EXE lit tout cela dans un fichier à votre place — en-têtes, bibliothèques, icône, signature — dans le navigateur, sans l'exécuter. Et si vous voulez essayer dès maintenant la voie sans installation, le lanceur est ici : déposez un .exe et il s'exécute dans l'onglet, sur votre propre machine. Ce qui fonctionne et ce qui ne fonctionne pas est exposé sans détour dans le guide de compatibilité.
